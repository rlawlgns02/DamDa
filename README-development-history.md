# DamDa

상황에 맞는 정보만 담아 공유하는 디지털 명함 웹 앱입니다.

## 현재 버전 실행 순서 (2026-09-21 기준)

PowerShell에서 아래 명령을 한 줄씩 순서대로 실행합니다. 각 명령이 정상적으로 끝난 것을 확인한 뒤 다음 명령을 실행하세요. 테스트 오류가 발생하면 오류 내용을 확인하고 해결한 뒤 진행합니다.

### 1. 처음 설치하거나 변경 후 전체 검증할 때

```powershell
cd D:\dev\Damda\DamDa
npm install
npm run check
npm test
npm run test:db
npm run test:browser
npm start
```

| 순서 | 명령 | 역할 |
|---|---|---|
| 1 | `cd D:\dev\Damda\DamDa` | `package.json`이 있는 실제 프로젝트 폴더로 이동합니다. |
| 2 | `npm install` | 실행·빌드·테스트에 필요한 패키지를 설치합니다. 처음 실행할 때나 의존성이 변경됐을 때 실행합니다. |
| 3 | `npm run check` | JavaScript 문법 오류를 검사합니다. 앱 기능을 실행하는 테스트는 아닙니다. |
| 4 | `npm test` | 명함 데이터 변환과 공개 항목, 계정 전환 중 공유·저장 격리, 부분 저장과 로그아웃 처리를 검사합니다. |
| 5 | `npm run test:db` | 로컬 PostgreSQL 엔진에서 DB migration, 권한 복구, 사용자 간 데이터 격리와 공유 생성·조회·종료를 검사합니다. 운영 DB를 수정하지 않습니다. |
| 6 | `npm run test:browser` | Edge에서 실제 화면을 조작해 가입·로그인·저장·공유·다운로드·반응형 화면 등을 검사합니다. 실제 Supabase SDK와 모의 API를 사용하며 운영 계정을 만들지 않습니다. |
| 7 | `npm start` | 앱을 자동 빌드한 뒤 로컬 서버를 실행합니다. 터미널에 표시되는 주소를 브라우저에서 엽니다. |

브라우저 테스트는 Microsoft Edge가 설치된 환경을 기본으로 사용합니다. 테스트가 끝나면 기존 연결 설정으로 자동 재빌드합니다.

기본 접속 주소는 `http://127.0.0.1:4173/DamDa/`입니다. 포트가 사용 중이면 다음 포트를 시도하므로 **터미널에 출력되는 실제 주소**를 확인하세요. 서버를 사용하는 동안 터미널을 열어 두고, 종료할 때는 `Ctrl+C`를 누릅니다.

현재 앱의 로그인·저장은 `config/supabase.json` 등에 설정된 Supabase를 사용합니다. 아래 과거 기록의 `admin / 1234` 체험 로그인 설명은 현재 운영 앱의 로그인 방법이 아닙니다.

### 2. 설치와 검증을 마친 뒤 다시 실행할 때

```powershell
cd D:\dev\Damda\DamDa
npm start
```

매번 패키지 설치와 전체 테스트를 반복할 필요는 없습니다. 코드를 변경했다면 해당 변경에 맞는 검사를 다시 실행합니다. `npm start`가 시작할 때 빌드하므로 실행 전에 별도로 `npm run build:pages`를 입력할 필요는 없습니다.

### 3. 실행 중 화면 코드를 수정했을 때

서버는 변경 사항을 자동 빌드하지 않습니다. `dist/` 파일을 수정했다면 별도 PowerShell 창에서 다음 명령을 실행하고 브라우저를 새로고침합니다. 서버를 종료한 뒤 `npm start`로 다시 시작해도 됩니다.

```powershell
cd D:\dev\Damda\DamDa
npm run build:pages
```

`npm run build:pages`는 배포·미리보기용 파일을 `_site/`에 생성합니다. 서버를 실행하거나 인터넷에 배포하지는 않습니다.

### 4. `package.json`을 찾을 수 없다는 오류가 발생할 때

`PS D:\dev\Damda>`에서 `npm install`을 실행하면 실제 프로젝트보다 한 단계 위이므로 `ENOENT` 오류가 발생합니다. 다음과 같이 이동한 뒤 다시 실행하세요.

```powershell
cd D:\dev\Damda\DamDa
npm install
```

정상 작업 위치는 **`PS D:\dev\Damda\DamDa>`**입니다.

## 이전 실행 방식 (개발 초기 기록)

아래 내용은 이전 버전의 개발 기록입니다. 실행 명령, 포트, 인증·저장 방식은 위의 현재 버전 안내와 [README.md](README.md)를 기준으로 확인하세요.

처음에는 `npm install`, 이후 `npm start`를 실행하고 터미널에 표시되는 주소로 접속합니다. 기본 포트는 5173이며 이미 사용 중이면 다음 포트를 사용합니다.

체험 로그인: **admin / 1234**

로그인, 3단계 회원가입, 정보 공개 선택, 사용자 정의 항목, 프로필 사진, 프리셋, 3가지 명함 디자인, 공유 링크와 QR 코드를 제공합니다. 모바일 레이아웃과 움직임 줄이기 설정을 지원합니다.

실제 인증 서버 없이 동작합니다. 가입은 온보딩 체험이며 비밀번호는 저장하지 않습니다. 프로필과 로그인 상태는 현재 탭의 sessionStorage에 보관하며, 아이디 기억하기를 선택한 경우에만 아이디를 localStorage에 저장합니다.

## 명함 공유와 다운로드

1. 공개할 정보와 사진을 선택하고 **명함 만들고 공유하기**를 누릅니다.
2. 만들어진 링크를 복사하거나 QR 코드를 보여줍니다. QR 이미지도 저장할 수 있습니다.
3. 받는 사람은 로그인 없이 명함을 열고 **명함 이미지 저장(PNG)** 또는 **연락처 저장(VCF)**을 누릅니다. 사용자 정의 항목은 연락처 메모에 포함됩니다.

공유 명함은 이 PC의 `data/cards/`에 저장됩니다. 선택하지 않은 항목과 숨긴 이름은 저장하거나 공유하지 않습니다. 사진은 공유 명함과 PNG 이미지에 포함되며, VCF에는 텍스트 정보만 담깁니다. 공유 시점의 고정된 사본이므로 이후 수정한 내용은 새 명함을 만들어 공유해야 합니다. 서버 재시작 후에도 파일이 남아 있으면 명함을 열 수 있습니다.

외부 업로드나 배포는 없습니다. 서버는 같은 Wi-Fi 기기에서도 접속하도록 `0.0.0.0`에 바인딩합니다. 공유 주소에는 PC의 네트워크 IP를 사용하므로 **같은 Wi-Fi 연결과 실행 중인 서버가 필요**합니다. 네트워크가 여러 개면 공유 화면에서 실제 Wi-Fi 어댑터를 선택하세요. Windows 방화벽이나 공유기의 기기 간 통신 제한 때문에 접속이 안 될 수 있습니다. 앱은 방화벽 설정을 자동 변경하지 않습니다. IP나 실행 포트가 바뀌면 기존 링크의 주소도 바뀌므로 새 주소로 공유하세요. 외부 인터넷 공유에는 별도로 승인한 호스팅이 필요합니다.

## 검증

`npm run check` 및 `npm test`

## 적용된 워크스페이스 디자인

로그인 후 사이드 메뉴에서 내 명함과 명함함을 전환합니다. 프로필 사진 편집, 공개 정보, 프리셋 관리, 실시간 미리보기와 공유를 새 레이아웃에서 이용할 수 있습니다. 상단 **명함 저장하고 공유**는 공유 사본을 서버에 만들고 브라우저 명함함에 보관한 뒤 QR와 링크를 표시합니다. 새 프로필은 담다 블루 디자인으로 시작하며 기존 저장된 테마는 유지합니다. 모바일에서는 미리보기가 먼저 나오고 편집 영역이 이어집니다.

## 프리셋과 애니메이션

공개 정보 프리셋 영역의 **+ 프리셋 추가** 또는 각 프리셋 옆 **편집·삭제**를 사용합니다. 편집 폼에서 이름과 공개 항목을 직접 정한 뒤 **저장하고 적용**합니다. 프리셋을 삭제해도 현재 프로필과 저장한 명함은 삭제하지 않습니다.

화면 상단 **애니메이션 → 애니메이션 줄이기**로 이동 효과를 끌 수 있습니다. 기본값은 시스템 설정이며, 운영체제에서 동작 줄이기를 사용하면 앱에서도 효과를 줄입니다.


### 명함 스튜디오 UI

설정 버튼에서 화면 모드·언어·애니메이션을 선택합니다. 사진 모양·크기, 공개 이름, 명함함 분류와 프리셋 편집은 드롭다운 없이 선택 버튼으로 조작합니다.

명함을 마우스나 터치로 드래그하거나 방향키로 회전할 수 있습니다. 앞면·뒷면·회전 초기화 버튼도 제공됩니다. 뒷면 제목(60자), 문구(240자), 배경색과 패턴은 프로필 및 공유 명함에 함께 저장됩니다. 기존 PNG 저장은 앞면 이미지입니다.

검증: npm run check, npm test, npm run test:browser. 브라우저 테스트는 설치된 Microsoft Edge를 기본 사용하며 DAMDA_BROWSER_CHANNEL로 Playwright 채널을 지정할 수 있습니다. 브라우저 테스트는 임시 저장소와 임의 포트를 사용하고 테스트 후 종료합니다.
